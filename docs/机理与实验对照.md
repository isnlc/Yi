# 机理与实验对照

> 更新日期：2026 年 11 月 3 日。主口径为 219 条记录、48 题大集；原始结果见 `eval/results/large_evidence.json`。

## 1. 写入侧：先判断能不能记

| 机制 | 实际处理 | 目的 |
|---|---|---|
| 明确记录 | “帮我记一下……”直接进入准入检查 | 尊重用户明确意图 |
| 高置信隐式事实 | 明确长期偏好、计划和已发生事件可直接记录 | 用户不必每次说“请记住” |
| 待确认候选 | 表述含糊、稳定性不足的长期事实进入候选区 | 防止模型把猜测当事实 |
| 普通对话 | 问题、建议请求和闲聊不自动写库 | 避免什么都记 |
| 附件资料 | 文档正文、OCR 与个人记忆分库存放 | 防止第三方内容归属于用户 |
| 安全拦截 | 密钥、证件、支付标识、联系方式等不写入 | 降低敏感信息风险 |

LLM 只可给出语义候选；最终写入仍需本地规则、原文依据校验和用户权限。附件中的指令不具有系统权限。

## 2. 治理侧：把记录变成可更新的状态

结构化语义由 `topic / entities / facets / values / scope / excluded_entities` 组成。冲突判断同时使用日期和全局写入序：同日先写原计划、后写最终决定时，后者可成为当前版本。

| 记忆状态 | 含义 | 查询方式 |
|---|---|---|
| active | 当前有效或高活跃记录 | 常规检索 |
| superseded | 被新版本取代 | 历史与演变查询 |
| compressed | 低活跃但仍有依据的记录 | 档案回溯 |
| discarded | 主动淡忘的记录 | 用户恢复或受控回溯 |
| conclusion | 同主题长期演变和稳定模式 | 总结查询 |

最新大集产生 13 组冲突，完整方案全部形成已解决取代链；单模块对照没有独立冲突账本。

## 3. 查询侧：先判断需不需要记忆，再判断需不需要 LLM

| 回答模式 | 适用问题 | 处理链 |
|---|---|---|
| `retrieval_only` | 当前状态、时间、历史事实、明确配置 | 本地语义分析 → 三路检索 → 当前/历史裁决 → 模板回答 |
| `retrieval_llm` | 个性化建议、比较、综合分析 | 先检索个人证据 → LLM 仅基于证据推理 |
| `general_llm` | 不依赖个人记录的知识和创作 | 不读取记忆，直接通用回答 |

示例：

- “我现在喝什么咖啡？”：只查个人记忆，不需要 LLM 补充。
- “按我的口味推荐麻辣烫”：先查辣度等偏好，再由 LLM 生成建议。
- “麻辣烫有哪些口味？”：普通知识问题，不读取个人记忆。

宽泛时间回顾单独处理：

- “我最近做了什么？”：默认展开七天内的多条活动，不按 current 压缩。
- “最近有哪些咖啡记录？”：时间窗与咖啡对象同时过滤。
- “我最近一次跑步是什么时候？”：仍只取最后一次匹配事件。
- “我现在还在跑步吗？”：仍按当前状态裁决。

当真实最近七天没有相关记录时，可回退到最近有记录的同长度窗口，但回答必须显示实际日期范围，不将历史数据伪装为当前数据。

## 4. 检索侧：三路互补，证据边界独立

| 通道 | 作用 | 单独或组合结果 |
|---|---|---:|
| BM25 | 精确词项与事实召回 | 92.7% |
| 时间窗 | 将“国庆、十月以来、上周”等映射为日期区间 | 词法加时间 96.9% |
| 主题图 | 扩展同主题关键事件和演变关系 | 词法加主题图 94.8% |
| RRF | 融合不同排序，不要求分数同尺度 | 三路全开 100.0% |

确定性单轮检索在当前题集上为 100.0%。关闭多轮改写后结果不变，因此主实验不把 ReAct 作为必要贡献；该机制仅保留在在线深度模式中。

## 6. 关键消融与工程验证

| 实验 | 结果 |

| 关闭日历窗口 | 100.0% → 95.8% |

| 固定语义压力集 | 76/76 |
| 扩展语义压力集 | 126/126 |

四项智能体任务分别为记录抽取、冲突治理、证据检索和回答审核，并由统一编排器管理。该对照考察独立冲突治理和审计记录的作用，不以增加模型调用次数作为变量。
